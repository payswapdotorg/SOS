# W4 — Evidence + Observability Fabric

**Status:** READY FOR ARCHITECT DISPATCH
**Dependencies:** W2 merged on `main`
**Governing architecture:** `spec/architecture.md` §§3.7, 4, 9, 12–13; `spec/sos-meta-model.md`
**Requirements:** R9–R10, R21, R23–R24

## Goal

Provide the authoritative evidence boundary connecting observations from repository, runtime, environment and experiment-facing adapters to versioned System State subjects without making causal claims or turning missing data into success.

## Scope

- typed Evidence entity and evidence-kind vocabulary from the frozen meta-model;
- explicit availability/truth states for evidence results;
- provenance containing source/revision/time/environment identity;
- subject references to System State, graph nodes/edges and other governed artifacts;
- append-only evidence collection boundary;
- repository/static evidence adapter integration with W3 recovery output;
- generic OpenTelemetry-compatible event envelope for later runtime adapter work, without requiring telemetry infrastructure here;
- deterministic serialization and validation tests;
- evidence-quality metadata separating observation from intervention evidence;
- repository-resident checkpoint/evidence.

## Explicit exclusions

- causal learning or architecture memory (W5);
- candidate generation/search (W6);
- assurance/promotion/experimentation execution (W7–W8);
- redefining W2 graph/state semantics;
- asserting causality from observational evidence;
- treating unavailable telemetry as zero, empty or successful.

## Acceptance criteria

1. Evidence records preserve kind, source, subject, timestamp, environment, result, provenance, confidence and availability.
2. Observation, test, static-analysis, simulation, replay, shadow, canary, experiment, deployment, user outcome, business outcome, incident and rollback kinds are represented.
3. Failed, unknown, unsupported and unavailable states remain distinct from successful and empty results.
4. Every evidence record has provenance sufficient to reconstruct source revision and observation time.
5. Evidence can reference W2 System State and architecture graph artifacts without becoming a semantic authority over them.
6. Evidence quality identifies whether a record is observational or intervention-based; no causal conclusion is generated by W4.
7. Evidence collection is append-only and deterministic for a fixed input stream.
8. Repository/static adapter can emit evidence for W3 recovery outputs.
9. A telemetry event envelope can preserve source/resource/time/attributes without requiring a live collector.
10. Tests cover validation, truth states, provenance, append-only behavior and serialization.
11. W4 contains no causal knowledge, candidate search, assurance or promotion behavior.

## Verification

- focused unit tests;
- deterministic serialization tests;
- negative tests for missing provenance and invalid truth-state combinations;
- exact-head verification;
- repository-resident evidence report.

## Required PR evidence

Record exact base/head SHAs, dependency merge, requirement mapping, evidence kinds supported, deterministic verification, known blind spots and explicit causal/non-causal boundary.
