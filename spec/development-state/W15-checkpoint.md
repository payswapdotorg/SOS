## Known limitations (filled)

1. The gate certifies the repository state it runs against (the exact head
   recorded in `repoHead`); the committed report cites the implementation
   head per the W14 two-commit convention, and the tip re-run reproduces
   identical verdicts (regenerating would change only `repoHead`).
2. G06's subprocess evidence is environment-derived by definition (exit
   codes and the parsed count of the hermetic suite at that head); it is
   stable for a fixed head and is re-produced by any re-run — the exact
   counts are recorded in this checkpoint and the report.
3. The terminal-state (ROADMAP_COMPLETE) G10 semantics accept the final
   projection in the none-form ("none (roadmap complete)" / "[]" /
   "complete") or exact ledger equality; if the Architect's final
   projection uses a materially different phrasing, a review-time
   correction on this branch (extend-never-weaken) may be required —
   flagged now rather than discovered later.
4. The W1 §2 exemption relies on the PR-head object remaining resolvable
   in the repository (it resolves via the fetched
   `origin/work/w1-mission-value-context` ref in a full clone); a
   hypothetical future branch deletion would surface as a G08 dangling
   head claim — a truthful failure, not a false pass.
5. The gate is W15-scoped tooling: it reconciles the SOS-v1 program
   evidence; it does not validate the semantic content of any Work Order
   beyond the coverage reconciliations specified by the design.

## Risk / rollback (filled)

**Risk:** false confidence — a check passing although state is
inconsistent. Mitigations (the Work Order's own): every check has a
negative fixture in `tests/test_w15_final_gate_check.py` (including the
exemption guards — the §2 convention is topology-keyed and
resolvability-keyed, so a stale head cannot hide behind the label); the
gate never approves (reconciliation records facts; only the Architect's
sign-off completes — process §11); review-time items are explicitly marked
rather than silently assumed mechanical; the shipped baseline is
self-verified against the actual repository by the suite at every run.
Secondary risk: the report's G06 count drifting from a re-run — impossible
for a fixed head (the suite is deterministic and hermetic; counts are
exact). **Rollback:** ordinary Git revert of the merged W15 change — the
script and its tests are additive tooling touching no product code and no
frozen semantics; reverting removes the mechanical gate but not any
recorded evidence, and the W15 evidence files (report, checkpoint, design)
remain historical records of the gate run at the exact head.
